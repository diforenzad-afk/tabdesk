# Tabdesk

Turn every Firefox new tab into a small, customizable internet dashboard. Inspired by Omarchy's terminal aesthetic and Hyprland's tiled layout, Tabdesk puts your everyday tools in stacked or tabbed panels:

- **Checklists** for tasks and recurring to-dos.
- **Notes** for quick thoughts and reminders.
- **Quick links** for the sites you keep opening.
- **YouTube search** without an extra stop at the homepage.
- **Experimental product watches** for background availability checks on supported stores.

Your dashboard is stored locally in your Firefox profile. No accounts, analytics, remote code, bundler, or runtime dependencies.

## Install (development, temporary)

1. Open `about:debugging#/runtime/this-firefox`.
2. Choose **Load Temporary Add-on…** and pick `extension/manifest.json`.
3. Open a new tab.

A temporary add-on disappears when Firefox restarts. Loading it this way is only for local development and needs no signing. For an install that survives restarts, use the signed path below.

Requires Firefox 128 or newer.

## Install (persistent, signed by Mozilla)

This repository only prepares an unsigned ZIP. Nothing is uploaded, submitted or signed by any command here, and no signed `.xpi` is committed.

### Build the unsigned package

```sh
npm ci
npm run package:unsigned
```

`npm ci` needs network access to the npm registry. `npm run package:unsigned` runs the manifest static checks and `web-ext lint`, then writes `web-ext-artifacts/tabdesk-0.1.0-unsigned.zip` using only the files under `extension/`. It makes no network request to Mozilla and submits nothing.

The ZIP is an **unsigned upload package for AMO**, not an installable signed XPI — renaming it to `.xpi` will not make Firefox accept it. Rebuilding from the same source produces the same contents and filename, but byte-identical archives are not guaranteed (timestamps and compression may differ).

### Sign it yourself (manual, browser)

1. Sign in to <https://addons.mozilla.org/developers/> with your own Mozilla account.
2. Choose **Submit new add-on** and select **On your own** (unlisted distribution).
3. Upload `web-ext-artifacts/tabdesk-0.1.0-unsigned.zip`.
4. Answer Mozilla's current disclosure and review prompts honestly.
5. When asked for the original source, provide this repository's `extension/` sources: they are untransformed native JavaScript with no minification or build tooling.
6. Wait for signing and any review.
7. Download the signed `.xpi` from AMO.
8. In Firefox open `about:addons`, use the gear menu → **Install Add-on From File**, pick the `.xpi`, then restart Firefox to confirm the add-on stays installed.

Notes:

- Signing requires Mozilla's online signing service. `web-ext lint` passing is not a guarantee that AMO will approve the add-on.
- **Unlisted** means it is not in the public AMO directory, but it is not secret or access-controlled — anyone with the signed file or its URL can install it.
- Do not disable Firefox's add-on signature enforcement; a signed build is the supported persistent path.
- There is no auto-update hosting in this repository. To ship a change, bump `version` in `extension/manifest.json`, rebuild, and sign again through AMO with the same stable add-on ID (`tabdesk@example.local`).

### Moving from a temporary install

The temporary and signed installs use the same add-on ID, but that alone does not guarantee Firefox carries data from one to the other. Before switching, copy important notes, checklists, links and watched product URLs somewhere safe (for example into a text file outside the extension). If you want a rollback, you may back up your Firefox profile with Firefox fully closed; Firefox has no built-in export/import for this extension's storage, and uninstalling the add-on removes its storage. Do not uninstall the temporary add-on unless you have already saved or backed up what you need.

## Using it

- **+ widget** in any panel header adds a checklist, note, quick-links collection, YouTube search or watch panel.
- Use ↑ / ↓ / ✎ to reorder, rename or move a widget between the four panels. ✕ deletes after confirmation.
- Each panel header toggles between **stacked** (the default) and **tabs**. The mode and active tab are saved. In tabs mode, ← / → / Home / End move between tabs, and hidden tabs keep their unsaved note drafts.
- Notes keep a dirty draft while other panels update. **save** or **Ctrl/Cmd+Enter** commits it. If the same note was changed elsewhere, the draft is kept and you can reload or overwrite deliberately.
- Links must be HTTP(S) URLs without embedded credentials. Fragments are stripped. Unsafe schemes are rejected.
- Product watches only accept HTTPS product URLs. Adding one asks Firefox for access to that exact origin (`https://shop.example.com/*`); site access is never requested at install time and no product page is fetched until you ask for a check.

Limits: 40 widgets, 10 watched products, 100 items per checklist, 50 links per collection, 20 000 characters per note. Text is inserted with `textContent`, never HTML.

## Availability checks

- One alarm per hour while Firefox is running; checks run sequentially and are coalesced if one is still in progress. A manual check has a 60-second cooldown, and checking one product only fetches that product.
- Requests use `credentials: 'omit'`, `referrerPolicy: 'no-referrer'` and fail closed on redirects. Only HTML responses up to 1 MiB are read, with a 15-second total timeout including the body.
- Detection is conservative: JSON-LD `Product`/`Offer` nodes with the exact `https://schema.org/` (or `http://schema.org/`) `InStock`, `OutOfStock` or `SoldOut` identifiers. Missing, malformed, contradictory, ambiguous, multi-product or truncated pages are reported as unknown. Script scanning is linear and bounded; unterminated or oversized JSON-LD fails closed.
- A result is a cached observation made when the check ran — not a live guarantee or a purchase recommendation. Pages that hide availability behind JavaScript, refuse the request or use another schema will show unknown.
- The permission check and exact origin are re-verified for every request. If a product is removed or edited mid-check its result is discarded.

Known limitation: hostname checks reject localhost and obvious private IPv4/IPv6 literals, but DNS rebinding can still point a public hostname at a private address. Treat watched URLs as trusted; this extension is not a security boundary.

## Data and privacy

- State lives in `browser.storage.local` under `tabdesk.state.v1`, unencrypted, in your Firefox profile. Anyone with access to the profile can read it.
- There is no sync, telemetry, analytics or remote configuration operated by this extension, and no data is sent to its author. The manifest declares `data_collection_permissions.required: ["none"]` for the developer.
- A product watch does make network requests: when you ask for a check, the HTTPS URL you chose is requested from that shop, which receives normal request metadata (such as your IP address and user agent) as any page visit would. Watch requests use `credentials: 'omit'` and `referrerPolicy: 'no-referrer'`, so they send no cookies, auth credentials or referrer — but they are still requests to a third-party site.
- YouTube search and link widgets perform ordinary navigation to youtube.com or the link target; normal browser/site sessions apply there, not the watch request policy.
- Uninstalling the extension removes its storage.
- Screenshots of the smoke run are written to `artifacts/`; they are git-ignored.

## Development

```sh
npm install
npm run check     # eslint, unit tests, manifest/static checks, web-ext lint
npm run smoke     # mocked Chromium UI smoke + screenshots
npm run package:unsigned  # build web-ext-artifacts/tabdesk-<version>-unsigned.zip
```

`npm run check` runs:

- `npm run lint` — ESLint over the extension, scripts and tests.
- `npm test` — Node's test runner for state, URL, availability and watch logic (no network).
- `npm run check:manifest` — asserts MV3, the event-page background, the permission/CSP posture, packaged files and the absence of inline/remote code.
- `npm run lint:ext` — `web-ext lint` over `extension/`.

`npm run package:unsigned` re-runs the manifest and `web-ext lint` checks, then builds the unsigned AMO upload ZIP into the git-ignored `web-ext-artifacts/`. It does not contact Mozilla, upload, submit or sign anything.

`npm run smoke` serves `extension/` on localhost, injects a mocked `browser.*` API backed by the real state module, blocks every non-localhost request and exercises CRUD, persistence, panel ordering, two-tab draft conflicts through real `storage.onChanged` events, scoped watch checks, stacked/tabbed switching and permission denial in headless Chromium. It writes `artifacts/desktop.png`, `artifacts/mobile.png` and `artifacts/tabbed.png`. **This is not Firefox extension validation** — the API is mocked and the page is loaded over HTTP. No automated command loads a real Firefox profile, so Firefox extension API and permission behaviour still requires loading the add-on manually.

Layout: `extension/background.js` owns storage and serialises mutations; `extension/lib/state.js` validates and applies them; `extension/lib/urls.js`, `availability.js` and `watch.js` contain the URL, detection and polling logic; `newtab.js` renders the desk.
